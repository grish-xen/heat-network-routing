# Общие примеры режима глубины

Это заданные графы и рассчитанные представления, **не результаты работающего DEPTH solver**. Соглашения — [DEPTH_CONTRACT.md](../../../docs/DEPTH_CONTRACT.md).

В каждой папке:

- `input.geojson`: настоящий вход WGS 84 для текущего парсера.
- `metric-case.json`: описание для тестов, srid=32637. Геометрии inputObjects и xy — метры. candidate соответствует RouteCandidate, expectedVariant — CalculatedVariant. При загрузке в Java xy преобразуется в JTS с SRID 32637, enum — в Model enum, inputObjectId — в ObjectId с сохранением типа. Это не второй production DTO и не формат загрузки API.
- `expected.geojson`: один допустимый профиль и сводка; служебные ID иллюстративны.

| Каталог | Сценарий | Контроль |
| --- | --- | --- |
| flat | 100 м без препятствий | 3 м, ДУ80, одна существующая врезка, промежуточная вершина |
| gas-below | Под газопроводом | 3,4 м, переходы по 4 м |
| gas-above | Над газопроводом | 2,4 м, переходы по 6 м; высота новой сети 0,16 |
| cable-below | Под кабелем | 2,7 + 0,2 + 0,5 = 3,4 м |
| network-below | Под существующей сетью ДУ300 | 3 + 0,45 + 0,5 = 3,95 м, переходы по 9,5 м |
| road | Под полигональной дорогой | Спецучасток 37…63 м: полигон 40…60 плюс по 3 м; глубина 3 |
| branch | Два потребителя, общая камера | ID 1 и "1" различны; общий ДУ125, далее ДУ80/100; непрерывная глубина |

`manifest.json` перечисляет сети. `negative-cases.json` содержит десять замен JSON Pointer в копии expectedVariant. Проверяется присутствие ожидаемого кода, дополнительные ошибки допустимы. Для теста всего калькулятора пересчитайте стоимость изменённого профиля, чтобы не смешивать причины отказа.

`profile-units.json` — отдельные проверки стоимости, деления на 3 м, интерполяции и недостаточного места для перехода. Это части профиля, поэтому P1 к их концам не применяется. Невозможность перехода в фиксированном интервале не доказывает невозможность другого планового маршрута.

## Проверка из корня проекта

```sh
python scripts/check_repository.py
mvn -f backend/pom.xml verify
```

Python проверяет числа, графы, глубины, стоимости, ссылки, отрицательные случаи и согласованность API. Java-тест DepthFixtureInputTest читает входы настоящим парсером, проверяет восстановление метрических геометрий и допустимость плановых кандидатов существующим 2D-калькулятором. Полные тесты DEPTH-решателя ещё должны добавить №2 и №3.

После установки `scripts/requirements-checks.txt`:

```sh
python scripts/check_depth_schemas.py
```

## Регенерация

Нужны Python 3.9+, JDK 11 (JAVA_HOME) и собранный backend JAR:

```sh
python scripts/generate_depth_fixtures.py
python scripts/check_repository.py
```

Генератор извлекает Proj4J из JAR во временную папку и запускает `scripts/ProjectDepthFixtures.java`. Новых библиотек Python нет. Другой JAR: `--backend-jar PATH`.

Перезаписываются семь каталогов сетей, положительные API-ответы, manifest и представление каталога. Отрицательные тесты и контрольная арифметика хранятся независимо. Регенерация не заменяет проверки корректности правил.
