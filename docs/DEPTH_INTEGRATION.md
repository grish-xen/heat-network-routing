# Интеграция DEPTH — 28 сентября 2026

Ветка `feature/depth-integration` объединяет каталог участника 2 из PR #21, построитель профиля участника 3 из PR #22 (`08b38d9`), экспорт из PR #18 и дедупликацию из PR #20. Исходники `calculation` совпадают с веткой участника 3. Frontend не изменялся.

POST `/api/jobs` принимает `mode=2d` и `mode=depth`. JobService передаёт режим координатору, маршрутизатор выдаёт плановые кандидаты, калькулятор строит глубины и вызывает независимый валидатор. Сохранение и SUCCEEDED происходят после экспорта, построения карты и закрытия Dataset. Неизвестный mode даёт HTTP 400; ошибка входа после загрузки — FAILED. Старый fixture `unsupported-mode.json` описывает исторический сервер.

## Независимая проверка

`routing.DepthSpatialValidation` использует общий `RulesCatalog.loadDepth()`, не вызывает построитель профиля и не доверяет `crossedObjectIds` при поиске препятствий. Проверяет конечность/минимум глубин, уклон по геометрической горизонтальной длине, деление на пороге Kгл, P1, размах глубин в узлах и постоянство цепочек спецпроходов P3. Прежние плановые проверки выполняются также в DEPTH, включая запрет пересечений новых трасс вне общего узла.

Просвет проверяется во всей связной области перекрытия габаритов: начало и конец интервала пересчитываются в глубины по накопленной длине. Газ/кабель используют размеры из дополнения; существующая сеть — высоту и ширину по ДУ из общего каталога. Глубина в точке пересечения осей сама по себе недостаточна. Буфер строится с 16 сегментами на четверть окружности и небольшим наружным расширением, чтобы аппроксимация не уменьшала габарит; на границе это может консервативно отвергнуть допустимый профиль. Только связный начальный контакт с существующей сетью у присоединения освобождён от вертикального просвета; повторное пересечение проверяется.

`DEPTH_*`-диагностики содержат segmentId и, когда известно, inputObjectId. Калькулятор добавляет candidateId. Отказ передаётся маршрутизатору через feedback, после чего он пробует оставшиеся планы. Исчерпание ограниченных попыток маршрутизатора и maxCandidates координатора сохраняется как SEARCH_BUDGET_EXHAUSTED; пустой Optional без явного сигнала этот код не создаёт. Диагностика поиска сохраняется также у успешного частичного результата.

## Проверки

- `DepthCalculationTest`: построитель участника 3, семь примеров, стоимость, близкие препятствия, ветвление и невозможный переход.
- `DepthSpatialValidationTest`: семь готовых профилей, общий набор отрицательных замен, NaN/Infinity, нулевая длина, P1/P3, просвет вне точки пересечения осей и накопление малых отклонений вдоль спецпрохода.
- `DepthIntegrationTest`: настоящий поиск → расчёт → независимый валидатор → координатор → экспорт → хранение → перезапуск и постраничная карта на семи примерах. Подключаются все потребители. Готовые графы вместо расчёта не подставляются.
- `JobApiTest`: настоящий multipart POST DEPTH → SUCCEEDED → сводки/результат/карта/bounds на семи примерах. Для газа проверяется реальное изменение глубины; ошибочный вход не публикует результат. Существующие 2D-тесты сохранены.
- Проверка собранного JAR через `scripts/smoke_api.py`: газовый пример в DEPTH и конкурсный GeoJSON (144 объекта) в обоих режимах. На конкурсном наборе подключены 17/17 точек: 2D — 50 объектов карты результата, DEPTH — 62. Score соответственно 24.5599468527 и 24.5599468524; API использует готовые суммы без пересчёта. Побитового совпадения сумм разных нарезок графа эта проверка не требует.

Воспроизводимый запуск после старта backend:

```sh
python scripts/smoke_api.py --mode depth --input test-data/synthetic/depth/gas-below/input.geojson --require-full-connection
python scripts/smoke_api.py --mode depth --input test-data/competition-corrected.geojson --require-full-connection
python scripts/smoke_api.py --mode 2d --input test-data/competition-corrected.geojson --require-full-connection
```

HTTP DEPTH на газовом примере включён в GitHub Actions после сборки JAR; полный backend проверяется на Java 11. Демонстрационные маршруты и цены fixtures не обязаны совпадать с выбранным маршрутом решателя.

## Границы результата

Это серверная интеграция D3. Настоящие профиль/3D проверены в браузере на синтетических и конкурсном наборах; результаты и замечания участнику 4 — [DEPTH_BROWSER_CHECK.md](DEPTH_BROWSER_CHECK.md). Приёмка D4/D5 остаётся открытой до исправления замечаний и оставшихся проверок. Целевое развёртывание Ubuntu, 50 одновременных пользователей и вход 3 ГиБ этой проверкой не подтверждены. Поиск ограничен бюджетом и принятой P1–P4 policy, не гарантирует глобальный оптимум или доказательство невозможности подключения. Полный перебор сложных наложений и дополнительная приёмка D4/D5 продолжаются.
