# Исправление поиска маршрутов — 28 сентября 2026

База: `91ee9eb`, PR #15 участника 2. Изменения routing согласованы владельцем модуля через участника 1.

## Что было не так

- Перед ответвлением от построенной сети перебирались многочисленные неудачные прямые присоединения. При увеличении радиуса одни и те же присоединения проверялись повторно.
- Приоритеты элементов очереди A* менялись после добавления; устаревшие записи повторно обрабатывались.
- Состояние поиска учитывало положение, но не направление входа. При ограничении поворота в 90° это могло исключить допустимый обход.
- Последний отрезок до цели не проверялся, а замена последней вершины создавала непроверенный срез пути.
- Геометрия принятых трасс заново создавалась при проверке каждого шага; свободные связи камеры могли устареть между попытками разных целей.

## Исправления

После ближайшего прямого присоединения поиск пробует ответвления, затем остальные прямые варианты и более крупные сетки. Повторные пары «присоединение + шаг сетки» пропускаются; доступность камеры проверяется перед попыткой.

В очереди используются неизменяемые оценки и пропуск устаревших записей. Состояние включает направление входа. Пространственные проверки выполняются только при улучшении пути. Геометрия принятой трассы хранится один раз, перед пересечением проверяются её границы. Последний отрезок проверяется теми же правилами, что и другие шаги, проверенные вершины сохраняются. Поиск реагирует на прерывание потока.

Контракты API и калькулятора не менялись. Инженерная и пространственная проверка калькулятором остаётся обязательной. Число кандидатов и лимит расширений не увеличивались.

Это отдельные локальные замеры, не статистический бенчмарк. Промежуточная версия без исправления направления входа работала быстрее, но не проходила искусственный сценарий обхода препятствия; в итоговую версию она не включена.

Итоговый конкурсный вариант: длина 3684,919 м; стоимость 482 328 180,12 руб.; штраф 0; score 24,5599468527. Карта содержит 144 входных объекта и 50 объектов результата. `/variants`, скачанный GeoJSON, страницы карты и объединённые bounds проверены скриптом `smoke_api.py`. Результат не доказывает минимальность стоимости.

Добавлены искусственные проверки: препятствие на последнем отрезке при близкой и дальней цели; прерывание поиска; пять потребителей с ответвлениями при ограниченной степени корневой камеры, с оценкой настоящим калькулятором. Конкурсный HTTP-сценарий с `--require-full-connection` добавлен в CI наряду с синтетическим.

## Повторение проверки

Запустить backend, затем из корня репозитория:

```sh
python scripts/smoke_api.py --input test-data/competition-corrected.geojson --require-full-connection --report ../competition-report.json
```

Локальные журналы и отчёты этого прогона: `.build-tools/routing-fix-run` вне репозитория; полный журнал Maven: `.build-tools/routing-fix-final-verify.log`.

Остаются ограничения: конечная сетка и бюджет поиска, отсутствие гарантии полного подключения произвольного набора и инженерной оптимальности. В этом прогоне не проверялись большие файлы, 50 одновременных конкурсных расчётов, отрисовка браузера и запуск Docker на целевой Ubuntu. Более ранний результат 5/17 в [INTEGRATION_CHECK.md](INTEGRATION_CHECK.md) относится к версии от 27 сентября.
