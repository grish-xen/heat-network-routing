# Приёмка изменений участника 4 — 29 сентября 2026

Актуальная повторная проверка после PR #32 — [DEPTH_D4_RECHECK.md](DEPTH_D4_RECHECK.md): исправления камеры и длинной полилинии подтверждены, остаётся общий бюджет двух слоёв. Ниже сохранён исторический отчёт первого прогона.

Проверена ветка `feature/depth-d4-advanced`, коммит `30ac8d6`, на backend из main `3a67346` (PR #30). Локальная ветка приёмки — `test/depth-d4-acceptance`. Реализация frontend участника 4 при проверке не редактировалась.

## Подтверждено

- Полный `mvn verify` на Java 11: 335 тестов, без ошибок и пропусков.
- Frontend: 87 тестов в 23 файлах, lint и production build прошли. Предупреждение: основной JS около 2,05 МБ, gzip 559 КБ.
- Настоящие JAR + Vite HTTP + Chrome/SwiftShader: `BROWSER_FAIL_ON_FINDINGS=1 node scripts/check_depth_browser.mjs` завершился с кодом 0; findings и pageErrors пусты.
- Сверены профили всех 20 путей: газовый пример, две ветви и 17 конкурсных потребителей; скачивание совпадает с экспортом, сводки — с результатом. Проверены 2D, неверный JSON, ошибки /map 500/413, fallback без WebGL, мобильный профиль.
- Четыре замечания из первоначального [отчёта](DEPTH_BROWSER_CHECK.md) больше не воспроизводятся: ошибки загрузки видимы, диапазон газа 2,44–3,0 м, подписи числового/строкового ID различимы, повторных React keys нет.
- Дополнительный настоящий клик в WebGL выбирает участок 2; газовый пример показывает две коммуникации. На ширине 390 px у документа нет горизонтального переполнения.

Обычный браузерный сценарий проверяет прежние ошибки. Его зелёный результат не закрывает все новые возможности D4. Расширенный сценарий ниже завершился с кодом **2: три замечания**, без необработанных ошибок страницы.

## Осталось участнику 4

1. **Выбор участка сбрасывает ракурс.** В `DepthScene.tsx` эффект зависит от `selectedSection`, уничтожает адаптер и создаёт его снова. Реальный клик по второй трубе заменил canvas; новый адаптер устанавливает начальную камеру. Выделение нужно обновлять с сохранением камеры/OrbitControls. Критерий: повернуть или приблизить сцену, выбрать несколько участков — ракурс остаётся прежним, выделение и свойства обновляются; только кнопка сброса возвращает общий вид.

2. **Сброс после сужения окна обрезает путь.** `three-adapter.ts` вычисляет `initialFrame` один раз. ResizeObserver меняет aspect, но сброс использует старую рамку. В браузере при переходе 1440 → 390 px газовая трасса обрезана слева и справа; проекция её концов после сброса имеет |x|=2,083 при видимом диапазоне до 1. Критерий: после resize и на мобильном экране кнопка сброса вписывает весь выбранный путь в текущий canvas. Пересчитать frame для актуального aspect.

3. **Предел GeoJSON features не ограничивает объекты сцены.** `MAX_DEPTH_SCENE_FEATURES=2000` применяется раздельно к входу и результату, затем каждое ребро полилинии становится mesh. Изолированный тест настоящих loader/converter передал один LineString: загрузчик принял 1 feature, преобразователь создал 2001 mesh коммуникации. Неограниченное разбиение возможно и у расчётной трубы. Нужен общий бюджет фактических сегментов/объектов до создания GPU-геометрии, с понятным сообщением и доступным экспортом; учитывать оба слоя. Критерий: одна длинная полилиния и сумма нескольких страниц/слоёв не обходят бюджет. Большой тест не рендерится, чтобы не перегружать GPU.

## Повторение

Поднять backend и frontend в HTTP-режиме по [DEPTH_BROWSER_CHECK.md](DEPTH_BROWSER_CHECK.md), настроить `PLAYWRIGHT_MODULE`, `BROWSER_EXECUTABLE`, `BROWSER_BASE_URL`, `BROWSER_OUTPUT` и `SOURCE_COMMIT`. Затем:

```powershell
$env:BROWSER_FAIL_ON_FINDINGS = '1'
node scripts/check_depth_browser.mjs
node scripts/check_depth_d4_browser.mjs
```

Первый сценарий записывает `report.json`. Второй — `d4-report.json`, снимки выбора участка и мобильной сцены; код 0 означает отсутствие замечаний, 2 — перечисленные findings, 1 — сбой утверждения/запуска. Проверка камеры использует публичный `cameraFrame` и известное поведение reset адаптера; её вывод дополнительно подтверждён просмотром снимка. После изменения механизма камеры нужно актуализировать эту диагностическую проверку, сохранив пользовательский критерий выше.

Локальные артефакты вне репозитория: `.build-tools/d4-browser-run/` и `.build-tools/d4-advanced-browser-run/`; логи сборок — `.build-tools/d4-*-verify.log`, `d4-frontend-*.log`. Приёмка выполнена на dev server и программном WebGL; production bundle собран, но отдельно в браузере не проверен. Длительная нагрузка, большие реальные файлы и аппаратный GPU этой проверкой не подтверждены.

После трёх исправлений: повторить расширенный сценарий до кода 0, затем подготовить единый запуск frontend/backend и финальную демонстрацию. D4 пока не закрыт полностью.
