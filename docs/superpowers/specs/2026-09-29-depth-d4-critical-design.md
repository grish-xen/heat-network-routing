# D4: завершение frontend DEPTH

## Цель

Закрыть четыре подтверждённых замечания и оставшиеся frontend-пункты браузерной приёмки D4, не меняя HTTP-контракт и не скрывая сбои загрузки под видом пустой глубинной модели. Изменения предназначены для демонстрации реальных DEPTH-расчётов через `VITE_API_MODE=http`.

## Первый PR: четыре подтверждённые ошибки

Первый PR содержит только четыре исправления из `DEPTH_BROWSER_CHECK.md`:

1. `ResultWorkspace` различает ожидание, ошибку, отсутствие глубинных участков и готовые данные для профиля/3D. Ошибка `/map` не подменяется пустым состоянием. Кнопка «Повторить загрузку» заново запрашивает данные; для HTTP 413 выводится объяснение, что сцена не смогла получить допустимый объём объектов. Экспорт результата и остальные элементы панели остаются доступными.
2. `DepthScene` показывает фактический минимальный и максимальный уровень глубины по всем частям выбранного пути. Подпись явно обозначает диапазон глубин пути.
3. Селектор конечного потребителя отображает ID с типом: строковое и числовое `1` имеют разные человеческие подписи. Значение `select` и поиск пути по-прежнему используют `objectIdKey`, поэтому тип не теряется.
4. `DepthProfile` создаёт уникальные ключи точек из типизированного ID ребра и номера части полилинии; смена пути не даёт React-предупреждений.

## Поведение и архитектура

`ResultWorkspace` выводит небольшое состояние загрузчика глубин рядом с областью визуализации. Пока запрос выполняется, профиль и 3D не получают пустой массив как конечный результат. При ошибке создаётся диагностическое состояние с сообщением и `refetch` всех глубинных запросов. Для 413 текст объясняет ограничение размера ответа и предлагает сузить/разбить задачу, но не утверждает, что данных нет.

Данные пути строятся только после успешного завершения всех запросов глубинной карты. Если запросы завершились успешно, но путей нет, остаётся нынешнее честное пустое состояние. Ошибки не меняют доступный URL экспорта и не блокируют выбор варианта.

Для подписей вводится presentation-helper на базе `ObjectId`: строка отображается как `строковый «value»`, число — как `числовой value`. Технический ключ остаётся `string:value` или `number:value` и не попадает в текст интерфейса без необходимости.

## Проверки

Тесты закрепляют: обработку pending/error/413 и повторной загрузки без потери ссылки экспорта; полный min/max диапазон глубин; различимые подписи двух ID с одним значением; уникальные ключи частей полилинии. Затем выполняются `npm --prefix frontend test`, `lint`, `build` и браузерный сценарий из `DEPTH_BROWSER_CHECK.md` на настоящем HTTP. Отчёт браузера должен быть без этих четырёх findings.

## Второй PR: оставшиеся frontend-пункты D4

### Предел и актуальность данных

Сцена получает явный общий предел `MAX_DEPTH_SCENE_FEATURES` для всех курсоров, а не только размер одной страницы API. Загрузка прекращается до создания сцены при превышении лимита и сообщает, что объём нужно сузить; экспорт остаётся доступным. Предел применяется к данным, предназначенным для profile/3D, и покрывается тестом курсорной пагинации.

React Query уже передаёт `AbortSignal` в HTTP-адаптер. Для depth-запросов не сохраняются `placeholderData` предыдущего варианта: при смене задачи, варианта или пути старая геометрия немедленно снимается, отменённый запрос не публикует результат. Выбранный потребитель сбрасывается при смене задачи/варианта. Состояния loading/error/empty используются и для этой смены.

### Коммуникации и выбор участка

Существующего API достаточно: `layer=input` возвращает ограничения с `restrictionType`, а сгенерированный `visualization-rules.v1.json` определяет их глубину, габариты и зазоры. Вторая сцена загружает эти объекты в тех же границах, что и результат, и отображает газопровод, силовой кабель и существующую теплосеть как отличимые полупрозрачные габариты. Дороги и трамвайные пути остаются поверхностными зонами, а не получают выдуманную глубину.

Каждая часть новой трубы становится выбираемой. Нажатие по ней обновляет панель свойств: порядковый номер части, глубины начала/конца, ДУ и горизонтальная длина; активная оболочка визуально подсвечивается. Нажатие по коммуникации не меняет выбранную трубу. Если сервер не возвращает одну из перечисленных групп объектов в `layer=input`, UI не подменяет её фиктивной геометрией; это конкретный сценарий для запроса участнику 1.

### Доступность и приёмка

Сброс камеры сохраняет детерминированный исходный кадр после resize и смены пути. При отсутствии WebGL 3D объясняет проблему, а карта (если доступна), SVG-профиль и экспорт продолжают работать. Стили не создают горизонтального overflow на ширине 390 px; панель управления и карточки сцены перестраиваются вертикально.

Проверки второго PR включают отмену задержанного запроса при быстрой смене варианта, суммарный лимит курсоров, выбор части, описание коммуникаций и отсутствие WebGL. Браузерная приёмка запускается с `BROWSER_FAIL_ON_FINDINGS=1` на `gas-below`, `branch`, `competition-corrected.geojson` и отдельном 2D-наборе. Ограничения, которые нельзя проверить без аппаратного GPU или дополнительных серверных данных, перечисляются в PR без выдачи их за закрытые.

## API-граница

Новый endpoint не требуется для коммуникаций D4: текущие `GET /map?layer=input` и build-resource правил содержат достаточные типы и вертикальные параметры. Если настоящий HTTP-ответ не включает `restrictionType` или нужную геометрию в границах результата, участнику 1 передаётся сценарий: «DEPTH-задача `gas-below`, выбранный вариант, bbox результата; frontend должен получить `gas_pipeline` из input-слоя с типизированным ID и LineString/Polygon геометрией». До согласования контракта frontend не создаёт эти данные сам.
