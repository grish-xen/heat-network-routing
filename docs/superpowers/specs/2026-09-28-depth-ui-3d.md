# Depth UI and 3D scene

## Goal

Show the calculated DEPTH variant in a clear, attractive and genuinely three-dimensional interface without changing the 2D workflow or hiding an unavailable backend behind fixtures.

## Approved interaction and visual direction

- The result workspace has a view switcher: **Карта**, **Профиль**, **3D-сцена**. A depth result opens on the 3D scene; a 2D result remains on the map.
- The 3D view is a light engineering model: a horizontal surface, underground design envelopes for pipes, a restrained palette, a selected route accent, a compact legend and a readable properties panel.
- Drag rotates the model, wheel zooms it and a "Сбросить ракурс" button restores the initial camera.
- In a branched graph the user selects an endpoint; only the route from the connection/source to that endpoint is rendered as the selected route. A simple chain is selected automatically.
- The interface always labels the vertical exaggeration (initial value: ×4) and does not change calculation values.
- No imaginary building height, terrain, or undisclosed engineering data is shown.

## Data and API rules

- `mode` has the union `'2d' | 'depth'` all the way from upload to `HeatNetworkApi.createJob`.
- HTTP requests retain server semantics. A 422 `UNSUPPORTED_MODE` is displayed as an error; depth fixture data is never substituted after an HTTP failure.
- Fixture mode may create a depth job using only `test-data/api/depth/*`; 2D fixture behavior must remain unchanged.
- Parse `start_node_id`, `end_node_id`, `depth_start`, and `depth_end` for `heat_network` features. Depth values are optional for 2D and must be finite non-negative values when present.
- The frontend imports `contracts/visualization-rules.v1.json` at build time. It uses its diameter dimensions and the documented vertical convention.
- GeoJSON stays WGS84. Before it reaches the 3D renderer, coordinates are transformed to a local metric plane (EPSG:32637), translated around a local origin, and rendered as `[x - x0, y - y0, -depth × exaggeration]`; longitude and latitude are never used as scene-space lengths.
- Complete map pages are requested using the existing bounds/page/cancellation path. A missing depth field, a null bounds response, or no selected path shows a clear empty state instead of an invented scene.

## Accessibility and resilience

- The view switcher is keyboard-operable with clear selected state and labels.
- WebGL failure leaves the map and longitudinal profile usable and tells the user what happened.
- Existing reduced-motion preference and small-screen layout continue to work.

## Out of scope

- Turning on the backend DEPTH algorithm or changing its endpoints.
- Visualizing real terrain or building heights.
- Ranking 2D and DEPTH variants together.
