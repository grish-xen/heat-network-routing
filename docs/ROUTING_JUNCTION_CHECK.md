# Повороты на стыках участков — 29 сентября 2026

Правило раздела 2 актуального [технического приложения](reference/current-technical-appendix.md): изменение направления трассы не превышает 90°. Деление линии в камере или техническом узле не должно скрывать недопустимый поворот. Проверка относится к плановой геометрии в обоих режимах.

`DefaultSpatialValidator` раньше проверял только внутренние вершины каждого LineString. Теперь проверяет также последний отрезок входящего ребра и первый отрезок каждого исходящего. Используется местное направление у узла, а не линия между концами всего ребра. Нарушение даёт `TURN_VIOLATION`, ID исходящего участка и пояснение с узлом и обоими рёбрами.

Две исходящие ветви не сравниваются между собой: Т-образное ветвление допустимо, если каждый путь от родителя поворачивает не более чем на 90°. У корня нет входящего нового ребра, поэтому сравнения с неизвестным направлением потока существующей сети нет.

В `GridRoutePlanner` первый шаг ответвления теперь использует входящее направление родительской трассы, включая короткий прямой выход к близкому потребителю. Предыдущая родительская точка служит только контекстом ограничения угла и не добавляется в новую ветвь при восстановлении пути.

## Проверки

- `JunctionTurnValidationTest`: восемь сценариев в TWO_D и DEPTH, всего 16 проверок. Недопустимый поворот в техническом узле и камере, одна недопустимая ветка, местное направление обоих рёбер, прямой и прямоугольный стык, Т-образное ветвление, независимые ветви корня. До исправления все десять отрицательных проверок падали: валидатор принимал такие варианты.
- `RoutingModuleTest`: поиск → настоящий калькулятор → валидатор → feedback на разветвлённой сети с пятью потребителями в обоих режимах. Дополнительный пример с целью позади ближайшего поворота родителя воспроизводил `TURN_VIOLATION` в обоих режимах до исправления поиска; после исправления оба потребителя подключаются без этого нарушения.
- Полный `mvn -f backend/pom.xml verify`, JDK 11: 285 тестов, без ошибок и пропусков.
- `python scripts/check_repository.py`: каталоги, контракты, примеры и ссылки согласованы.
- Собранный JAR, Windows / Java 11 / `-Xmx512m`: газовый пример DEPTH и конкурсный файл в обоих режимах прошли HTTP-проверки статуса, сводок, экспорта, карты и ошибочного входа. На конкурсном файле подключены 17/17 точек; объектов результата 50 в 2D и 62 в DEPTH. Score стал 24.7750345619 и 24.7750345616 соответственно (до исправления: 24.5599468527 и 24.5599468524). Учёт направления ветвления изменил выбранный план; прежнее значение score не является требованием теста.

Повторение HTTP-проверок после запуска backend:


## Границы

Изменены только реализация модуля 2, его тесты и общая документация. Построитель профиля, инженерный расчёт и frontend не менялись. Примеры подтверждают проверку стыков; они не доказывают оптимальность поиска или полноту проверки всех сочетаний препятствий. Следующая отдельная проверка — местный угол специального пересечения ломаных и полигональных ограничений.
