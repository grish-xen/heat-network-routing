## Стенд и воспроизведение

Windows, Java 11, Chrome 153.0.8010.53, headless с программным WebGL SwiftShader. Backend запускается из собранного JAR, frontend — через Vite с `VITE_API_MODE=http`. Обычные сценарии не перехватывают ответы API. Только отдельные проверки ошибок подменяют ответ `/map`, а проверка отсутствия WebGL отключает графический контекст браузера.

1. Собрать backend: `mvn -f backend/pom.xml verify` на Java 11; запустить JAR на `127.0.0.1:8080` с отдельными каталогами задач и входных данных.
2. Установить frontend по lockfile: `npm --prefix frontend ci`.
3. Запустить frontend с `VITE_API_MODE=http`: `npm --prefix frontend run dev -- --host 127.0.0.1 --port 5174 --strictPort`.
4. Установить `playwright-core` в отдельный каталог инструментов и указать путь к установленному Chrome. Проверенная версия — 1.63.0: `npm install --prefix ../.build-tools/browser playwright-core@1.63.0`.
5. Из корня репозитория выполнить (пример PowerShell):

```powershell
$env:PLAYWRIGHT_MODULE = (Resolve-Path '../.build-tools/browser/node_modules/playwright-core/index.mjs').Path
$env:BROWSER_EXECUTABLE = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:BROWSER_BASE_URL = 'http://127.0.0.1:5174'
$env:BROWSER_OUTPUT = (Join-Path (Resolve-Path '../.build-tools').Path 'depth-browser-run')
$env:SOURCE_COMMIT = git rev-parse HEAD
node scripts/check_depth_browser.mjs
```

Скрипт рассчитан на Vite dev server: для дополнительной сверки он импортирует HTTP-адаптер и преобразование профиля из исходников frontend. Это не проверка production bundle. `report.json` содержит сценарии, HTTP-статусы, найденные замечания и ошибки браузера; рядом сохраняются PNG и скачанные GeoJSON. По умолчанию код выхода 0 означает завершение обязательных проверок, а не отсутствие замечаний. Ошибка утверждения даёт 1; `BROWSER_FAIL_ON_FINDINGS=1` дополнительно даёт 2 при непустом списке замечаний. Артефакты содержат созданные локальные jobId и не коммитятся.

## Замечания для участника 4

1. **Ошибка загрузки глубин маскируется под отсутствие данных.** При успешном расчёте и HTTP 500 или 413 для `/map?layer=result…` вкладка 3D показывает «Нет участков с глубиной». Нет сообщения о причине и действия повтора. `ResultWorkspace.tsx` использует только `query.data`, не обрабатывает состояния ошибки/ожидания `depthQueries`. Критерий исправления: различать загрузку, ошибку и пустой результат, сохранять доступность экспорта и давать повтор. Для 413 предусмотреть понятное объяснение ограничения согласно плану D4.
2. **Подпись глубины в 3D вводит в заблуждение.** На `gas-below` указано «Глубина 3,0–3,0 м», хотя минимальная глубина внутри пути 2,44 м. `DepthScene.tsx` берёт лишь первое и последнее значения. Критерий: явно подписать глубины начала/конца либо показывать настоящий минимум/максимум выбранного пути.
3. **Потребители разных типов ID неразличимы по подписи.** В `branch` оба варианта списка называются `1`, хотя значения элементов — `string:1` и `number:1`; выбор технически работает и профили разные. Критерий: понятные разные подписи с сохранением исходного типа ID.
4. **Повторные React keys для точек профиля.** После открытия профиля `branch` или конкурсного набора консоль сообщает `Encountered two children with the same key`. `DepthProfile.tsx` использует ID исходного объекта для каждой части его полилинии. Критерий: уникальный ключ с учётом типа ID и номера части; нет предупреждений при смене пути.

Это замечания к текущему frontend, а не изменения контрактов или ошибки рассчитанных глубин. Автоматический сценарий сохраняет их в `findings`. Исправления реализации нужно согласовать с участником 4.

## Оставшаяся приёмка

- Смена нескольких ранжированных вариантов: в проверенных DEPTH-задачах решатель вернул один вариант. Проверены все пути внутри него.
- Масштабирование и точность восстановления камеры после сброса, мобильная 3D-сцена, другие браузеры и аппаратный GPU.
- Полный числовой контроль каждой промежуточной глубины независимой реализацией: SVG сверяется через штатное преобразование frontend, экспорт отдельно проверяется на концах сегментов и по длинам.
- Пересекаемые коммуникации и выбор отдельного участка в 3D, требуемые D4: текущий адаптер строит поверхность, трубы и направляющие, без препятствий и подсветки участка.
- Явный общий предел объектов сцены: `limit=1000` ограничивает страницу, но `loadMapFeatures` читает все курсоры и накапливает объекты. Проверки больших файлов и памяти этой приёмкой не покрыты.
- Диагностики успешного частичного расчёта, отмена при быстрой смене варианта/задачи, нагрузка и целевое развёртывание Ubuntu остаются отдельными проверками.
