# Проверка работающего API одной командой

Нужны Python 3.9+ и запущенный backend. Внешние Python-библиотеки не нужны. Из корня репозитория:

```sh
python scripts/smoke_api.py --require-full-connection
```

По умолчанию сервер — `http://127.0.0.1:8080`, вход — `test-data/synthetic/two-consumers/input.geojson`. Скрипт создаёт две настоящие задачи: расчёт входа и проверку повреждённого JSON. Данные остаются на сервере до штатной очистки по сроку хранения. Запускайте на тестовом сервере.

Проверяются:

- доступность backend, загрузка и переход задачи в SUCCEEDED / DONE;
- ранги и порядок score, совпадение `/variants` со сводками скачанного GeoJSON;
- пагинация карты с limit=2, отсутствие повторения курсоров, количество input-объектов;
- точное совпадение объектов карты каждого результата с экспортом;
- совпадение `/map/bounds` с объединёнными границами input и выбранного result (погрешность 1e-9 градуса);
- FAILED / INVALID_INPUT для повреждённого JSON и недоступность его результатов (409);
- Cache-Control: no-store на успешных ответах задач.

## Конкурсный пример и сохранение отчёта

```sh
python scripts/smoke_api.py --input test-data/competition-corrected.geojson --report ../smoke-report.json
```

Без `--require-full-connection` код 0 означает исправность проверенной цепочки API; частичное подключение допустимо и явно отмечается как `full_connection: false`. Отчёт содержит исходные ID неподключённых точек. Со строгим флагом такой результат даёт код 1. Это важно: SUCCEEDED не означает подключения всех потребителей.

Текущая конкурсная проверка оставляет 12 из 17 точек неподключёнными; поэтому в обязательном CI используется синтетический пример с полным подключением. Конкурсный сценарий доступен команде для диагностики, его ограничения не скрываются.

Другой сервер: `--base-url http://127.0.0.1:18080`. Ожидание расчёта: `--timeout 180` секунд на задачу; таймаут одного HTTP-запроса — `--request-timeout 15`. Дедлайн ожидания проверяется между HTTP-запросами и может быть превышен на длительность одного запроса. По истечении ожидания серверная задача не отменяется.

`--report` записывает JSON по указанному пути, родительский каталог должен существовать. `passed: false` и код завершения 1 означают ошибку проверки; диагностика находится в `error`. Десятичные числа JSON читаются без потери точности; score в отчёте записывается строкой.

## Границы проверки

Это проверка небольшого реального сценария, не нагрузочный тест: вход ограничен 16 МиБ, ответ — 32 МиБ, карта — 100 страниц по два объекта на слой/вариант. Скрипт собирает небольшие ответы в памяти. Для больших наборов используйте отдельные нагрузочные испытания. Проверка количества input-объектов не заменяет побайтовое сравнение входа и карты.

Скрипт не проверяет браузерную отрисовку, не доказывает инженерную оптимальность маршрута и не заменяет тесты модулей. В CI он запускается после `mvn verify` против упакованного JAR с отдельным временным хранилищем; процесс сервера завершается после проверки.
